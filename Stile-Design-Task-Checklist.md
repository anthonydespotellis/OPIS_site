# Stile design task — working checklist

> Working plan based on your request: design in Figma first, then build the microsite together. The brief’s four-hour estimate is a constraint to clarify, not a target for your full design process. Check the submission requirements before deciding how much exploration to include.

## 1. Decode the brief
- [ ] Extract the required audience, problem, goal, and key message
- [ ] List every required page, section, interaction, and content item
- [ ] Note technical, brand, accessibility, asset, and submission constraints
- [ ] Separate must-haves from opportunities to add polish
- [ ] Record open questions and assumptions
- [ ] Define what “done” means against the brief

## 2. Set the design direction
- [ ] Review Stile’s brand and relevant product context
- [ ] Research the audience and the task’s subject matter
- [ ] Gather visual references; identify patterns to use and avoid
- [ ] Write a short design rationale and success criteria
- [ ] Choose a visual direction: typography, colour, imagery, and tone

## 3. Plan the experience
- [ ] Map the user journey and primary action
- [ ] Organise the information architecture and page flow
- [ ] Draft or outline content for each section
- [ ] Sketch low-fidelity layouts
- [ ] Check that the concept answers the brief before polishing

## 4. Design in Figma
- [ ] Set up the file, pages, naming, and layout grid
- [ ] Create desktop wireframes
- [ ] Explore key visual concepts
- [ ] Select a direction and apply a consistent type and colour system
- [ ] Design the full desktop page and key interaction states
- [ ] Adapt the layout for mobile and tablet
- [ ] Check spacing, hierarchy, readability, contrast, and responsive behaviour
- [ ] Prototype the main path through the site
- [ ] Review the design against each brief requirement
- [ ] Prepare a concise handoff: rationale, screens, interactions, and assets

## 5. Prepare for the build
- [ ] Confirm the chosen design and what is in scope for the microsite
- [ ] Gather final copy, images, icons, fonts, and attribution/usage details
- [ ] Identify interactive behaviour and edge cases
- [ ] Note responsive breakpoints and important layout rules
- [ ] Agree what can be simplified if time becomes tight

## 6. Build together
- [ ] Translate the Figma design into reusable page sections
- [ ] Implement the responsive layout and visual system
- [ ] Add the agreed interactions
- [ ] Add metadata, page title, and favicon if required
- [ ] Check keyboard use, focus states, semantic structure, and contrast
- [ ] Compare the build with the Figma reference and refine

## 7. Review and submit
- [ ] Check the site at desktop, tablet, and mobile sizes
- [ ] Proofread copy and verify links, buttons, and assets
- [ ] Review against the brief’s must-haves and submission format
- [ ] Capture any requested screenshots or presentation material
- [ ] Package and submit the deliverables
- [ ] Write down what you would improve with more time

## Time and scope notes
- [ ] Confirm whether the four-hour estimate is expected working time, a suggested limit, or just their benchmark
- [ ] Track time by phase so you can explain your process honestly
- [ ] Protect time for responsive design, accessibility, and a final review
- [ ] If needed, reduce optional decoration before cutting required content or quality checks
